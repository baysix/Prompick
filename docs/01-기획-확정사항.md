# 프롬픽 기획 확정사항

> 원본 PRD에서 **변경된 내용**만 모았다. 여기 적힌 것이 PRD보다 우선한다.
> 결정일: 2026-09-16

---

## 1. 서비스 정체성 변경

원본 PRD는 "프롬프트를 숨기고 생성 결과만 파는 서비스"였다.
확정된 기획은 **"유행 프롬프트 아카이브 + 자동 제작 대행"** 이다.

인스타·쇼츠에서 AI 콘텐츠가 유행하고, 사람들은 댓글로 "이거 프롬프트 뭐예요?"를 묻는다.
그 수요를 정면으로 받는 것이 이 서비스의 출발점이다.

따라서 하나의 템플릿은 **두 가지 방식으로 소비**된다.

| | 프롬프트 제공 | 자동 제작 |
|---|---|---|
| 사용자가 얻는 것 | 프롬프트 원문 + 사용법 | 사진을 올리면 나오는 완성 결과물 |
| 대상 | ChatGPT·Gemini를 이미 쓰는 사람 | 도구가 없거나 직접 하기 번거로운 사람 |
| 가격 | 무료 또는 유료(기본 100 프롬비) | 무료 또는 유료(기본 100 프롬비) |

---

## 2. 재화 이름: 프롬비

크레딧의 서비스 내 이름은 **프롬비**다. 표기는 `🪙 100 프롬비`.

- 유료 템플릿의 **프롬프트 열람 가격**과 **자동 제작 가격**은 각각 따로 매긴다.
- 두 값의 **기본값은 100 프롬비**이며, 템플릿마다 관리자가 조정한다.
- 실제 가격 정책은 나중에 확정한다. 코드에 박지 말고 설정값으로 둔다.

---

## 3. 프롬프트 공개 정책

**템플릿마다 관리자가 공개 여부를 지정한다.**

| | 무료 | 유료 (기본 100 프롬비) |
|---|---|---|
| **프롬프트 공개** | 유입용. "진짜 알려주네" → 회원가입 | 프리미엄 아카이브 |
| **프롬프트 비공개** | 맛보기 제작. 결과는 주되 비법은 안 줌 | 독점 상품 (수익 핵심) |

---

## 4. 프롬프트 보호 규칙 개정 (PRD 2-3 대체)

원본 PRD의 "프롬프트 전면 비공개"는 **이중 구조**로 대체한다.

| 구분 | 내용 | 공개 여부 |
|---|---|---|
| `public_prompt` | 사람이 읽고 직접 쓰는 프롬프트 원문, 추천 모델, 사용 팁 | 템플릿 설정에 따라 공개 |
| `pipeline` | 실제 실행되는 내부 프롬프트, 모델 조합, 전처리·후처리, 파라미터 | **영구 비공개** |

### 반드시 지킬 것

1. 두 가지를 **같은 테이블의 플래그로 구분하지 않는다.** 테이블부터 분리한다.
   (한 필드를 조건부로 가리는 방식은 언젠가 반드시 샌다.)
2. `pipeline`은 어떤 사용자용 API 응답에도 포함하지 않는다. 사용자용 DTO와 관리자용 DTO는
   클래스 단위로 분리하고, 엔티티를 그대로 직렬화하지 않는다.
3. 외부 AI API 호출은 백엔드에서만 한다.
4. 작업 상태·결과 API에 내부 프롬프트, 모델명, 외부 작업 ID를 넣지 않는다.
5. 로그에 내부 프롬프트 원문을 남기지 않는다.
6. 외부 API 응답 원문을 그대로 사용자에게 전달하지 않고 `ErrorCode`로 변환한다.
7. 사용자용 응답에 파이프라인 필드가 없음을 검증하는 테스트를 작성한다.

`public_prompt`를 공개해도 우리가 튜닝한 파이프라인의 품질은 재현되지 않는다.
**공개가 오히려 자동 제작 구매를 유도하는 구조**가 되게 한다.

## 5. 접근 정책

```
비로그인 → 홈·탐색·검색·상세·예시 결과물까지 전부 열람 가능 (검색 유입 유지)
            └ [프롬프트 보기] [만들기]를 누르는 순간 로그인 유도
로그인    → 무료 템플릿 이용 / 프롬비로 유료 템플릿 이용
```

원본 PRD와 달리 **비로그인도 상세 페이지 전체를 볼 수 있다.** 실제 이용 시점에만 막는다.

## 5-1. 템플릿마다 다른 AI를 쓴다

한 템플릿 안에서도 단계마다 제공사가 다르다. 예를 들어 이렇게 조합한다.

```
Gemini(사진 읽기) → GPT 이미지(장면 만들기) → Higgsfield(영상화)
```

- **사용자는 이걸 알 필요도, 알 수단도 없다.** 진행 화면에는 "영상 만드는 중" 같은 일반 문구만 나간다.
- 관리자가 파이프라인 단계마다 모델을 고른다. 단계 유형에 맞는 모델만 후보로 나온다.
- `ai_models`에 모델을 등록해두고, 약관 확인과 API 키 준비가 끝난 것만 **켠다.**
  꺼진 모델은 새로 고를 수 없다.
- 각 모델의 1회 원가를 기록해, 파이프라인 원가 합계를 관리자 화면에서 보여준다.
  유료 템플릿 가격을 정할 때 마진 기준이 된다.

### 관리자가 실수로 노출하는 경우

시스템은 파이프라인을 절대 내보내지 않지만, 관리자가 제목이나 설명에 "Higgsfield로 만든"처럼
직접 적으면 그 방어가 무의미해진다. 편집 화면에서 사용자에게 보이는 글에 모델명이 들어가면
경고를 띄운다. 막지는 않는다 — 판단은 사람이 한다.

## 6. 등록 주체

**운영자 큐레이션만.** 사용자 투고(UGC)는 하지 않는다.
운영 루프는 다음과 같다.

```
인스타·쇼츠에서 유행 포착 → 프롬프트 역설계·검증 → 파이프라인 등록
→ 직접 생성한 결과물을 예시로 게시 → 트렌드 점수로 자동 노출
```

## 7. 기술 스택 변경

| 항목 | PRD 원안 | 확정 | 이유 |
|---|---|---|---|
| 백엔드 | Spring Boot 3 / Java 21 | **Spring Boot 4.1.1 / Java 25** | Initializr가 3.x를 더 이상 제공하지 않음. Java 25는 설치된 LTS |
| DB | 로컬 PostgreSQL (Docker) | **Supabase Postgres** | 관리형. 백업·모니터링을 직접 안 해도 됨 |
| 인증 | Spring Security OAuth2 | **Supabase Auth** | 카카오·구글을 Supabase가 처리. 백엔드는 JWT 검증만 |
| 파일 저장 | MinIO (Docker) | **Supabase Storage** | 서명 URL 내장. 한곳에서 관리 |
| 캐시 | Redis | **없이 시작** | 무료 횟수는 DB 테이블, 조회 중복 제거는 이벤트 테이블, 레이트 리밋은 인메모리로 충분. 서버 다중화 시점에 도입 |
| 로컬 환경 | Docker Compose | **불필요** | Supabase가 클라우드에 있음 |

DB에는 파일을 저장하지 않는다. `storageKey`만 저장한다.
(백업 폭증, 메모리 부담, 서명 URL·CDN 불가, 만료 삭제 시 VACUUM 부담)

### Supabase를 쓸 때 반드시 지킬 것

Supabase는 **프론트엔드가 DB를 직접 읽는 것을 전제로** 만들어진 도구다.
`anon key`만 있으면 브라우저에서 테이블을 조회할 수 있다.
우리 서비스는 파이프라인이 새면 사업 가치가 사라지므로 이 경로를 통째로 막는다.

1. **프론트엔드는 Supabase DB에 직접 접근하지 않는다.** 데이터는 항상 Spring 백엔드를 거친다.
   프론트에서 쓰는 Supabase 기능은 **로그인(Auth) 뿐**이다.
2. `public` 스키마의 `anon` / `authenticated` 권한을 전부 회수하고 RLS를 켠다.
   (`V2__rls_lockdown.sql`, 앞으로 만들 테이블에도 기본 적용되게 해둠)
3. `service_role key`는 **서버에만** 둔다. `NEXT_PUBLIC_` 변수에 절대 넣지 않는다.
4. RLS는 `ENABLE`만 하고 `FORCE`는 쓰지 않는다. FORCE를 켜면 정책이 없을 때
   테이블 소유자인 백엔드까지 막힌다.

### 연결은 두 개로 나눈다

Supabase는 포트에 따라 동작이 다르다. 하나로 합치면 마이그레이션이 깨진다.

| 용도 | 포트 | 모드 | 주의 |
|---|---|---|---|
| 앱 쿼리 (JPA) | 6543 | Transaction | `prepareThreshold=0` 필수. 안 끄면 *prepared statement already exists* 오류 |
| 마이그레이션 (Flyway) | 5432 | Session | DDL과 advisory lock 때문에 세션 연결이 필요 |

## 8. 아직 정하지 않은 것

- 유료 프롬프트 열람·제작의 실제 가격 (지금은 둘 다 기본 100 프롬비)
- 프롬프트 열람 구매의 성격: 영구 소장인지, 기간제인지
- 프롬프트를 산 사용자가 자동 제작을 할 때 할인해줄지
