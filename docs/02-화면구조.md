# 화면 구조

사용자는 네 가지를 한다. 메뉴는 그 순서를 따른다.

```
발견한다 → 판단한다 → 만든다 → 다시 온다
```

가장 약한 고리는 "다시 온다"이다. 한 번 만들고 끝나면 사업이 성립하지 않는다.
갤러리와 내 프롬프트가 그 자리를 맡는다.

---

## 사용자 화면

### 상단 메뉴

| 메뉴 | 주소 | 역할 |
|---|---|---|
| 영상 | `/explore?contentType=VIDEO` | 첫 갈림길. 이후 행동이 완전히 갈린다 |
| 이미지 | `/explore?contentType=IMAGE` | 〃 |
| 갤러리 | `/gallery` | 남이 만든 결과물. "이거 나도"가 일어나는 곳 |
| 요청 | `/requests` | "이 영상 프롬프트 찾아주세요". 운영자에게는 트렌드 레이더 |
| 가격 | `/pricing` | 프롬비를 모르면 결제까지 가지 못한다 |

공지사항·도움말·약관은 푸터에 둔다. 매일 누르는 것이 아니라 필요할 때 찾는 것이라,
상단에 두면 정작 중요한 메뉴를 밀어낸다.

### 흐름별 화면

**발견**
- `/` 홈 — 결과물 격자, 섹션별 추천
- `/explore` 탐색 — 종류·주제·요금 필터, 무한 스크롤
- `/search` 검색
- `/gallery` 갤러리

**판단**
- `/t/[slug]` 상세 — 예시, 결과 정보, 촬영 가이드, 프롬프트(공개 시), 만들기

**제작**
- `/t/[slug]/create` 만들기 — 가이드 → 업로드 → 옵션 → 확인
- `/jobs/[id]` 진행·결과

**다시 오기 (로그인 후)**
- `/my/jobs` 내 작업함 — 진행 중 / 완료 / 실패
- `/my/prompts` 내 프롬프트 — 산 프롬프트를 다시 보는 곳.
  이것이 없으면 "돈 내고 샀는데 어디 갔지"가 된다
- `/my/favorites` 찜
- `/my/credits` 프롬비 — 잔액, 사용·충전 내역
- `/my/settings` 설정 — 닉네임, 본인인증, 탈퇴

**신뢰**
- `/pricing` 가격 · `/notice` 공지 · `/help` 도움말
- `/terms` `/privacy` `/refund` — PG 심사 필수

## 관리자 화면

운영자가 매일 도는 순서가 곧 메뉴 순서다.

```
① 트렌드 포착 → 템플릿 등록      ② 잘 도는지 확인
      ↑                                ↓
④ 사람 관리 (문의·신고)  ←   ③ 돈 확인 (원가 vs 매출)
```

| 묶음 | 메뉴 | 하는 일 |
|---|---|---|
| — | 대시보드 | 오늘의 제작·성공률·매출과 원가, 손봐야 할 것 |
| 콘텐츠 | 템플릿 | 등록·수정·게시, 예시, 공개 프롬프트, 제작 방법(AI 선택) |
| | 카테고리 | 주제 관리 |
| | AI 모델 | 제공사별 모델 사용 설정, 원가 |
| | 요청 게시판 | 사용자가 올린 "만들어주세요" → 다음 템플릿 후보 |
| 운영 | 생성 작업 | 상태별 목록, 실패율, 평균 소요시간, 실패 사유 |
| | 갤러리 검수 | 공개 요청된 결과물 승인·거부 |
| | 신고 | 접수·처리 |
| | 공지사항 | 작성·게시 |
| | 운영 설정 | 무료 횟수, 워터마크, 보관 기간, 업로드 용량 |
| 회원·정산 | 회원 | 조회·정지·프롬비 수동 지급(사유 필수) |
| | 프롬비 원장 | 충전·차감·환불 전체 기록 |
| | 충전 상품 | 판매 상품 구성 |
| | 결제·환불 | 결제 내역, 환불 처리 |

### 대시보드에 원가를 반드시 넣는 이유

유료 템플릿 하나의 파이프라인 원가가 770원인데 프롬비를 얼마에 파느냐에 따라
**팔수록 적자**가 날 수 있다. 제작 건수만 보이는 대시보드는 이 사실을 감춘다.
그래서 건수 옆에 항상 원가를 같이 놓는다.
