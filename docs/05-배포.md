# 배포 (Render + Vercel)

프론트는 Vercel, 백엔드는 Render, DB와 저장소는 이미 쓰고 있는 Supabase. 셋 다 무료 범위 안에서
돌아간다. 다만 **무료인 것은 호스팅이고 제작은 아니다** — 아래 "돈" 절을 먼저 읽어라.

---

## 0. 먼저 알아야 할 것

### 돈이 나가는 지점

사용자가 만들기를 누를 때마다 **약 300원**이 OpenAI 계정에서 나간다. 호스팅비보다 이쪽이 훨씬 크다.

지금 템플릿이 전부 무료다. 공개하기 전에 정해야 한다.

| 무료 횟수 | 사용자 100명이 다 쓰면 | 매출 |
|---|---|---|
| 하루 3회 | 하루 9만원 | 0원 |
| 하루 1회 | 하루 3만원 | 0원 |
| 유료 전환 | 0원 | 프롬비 수입 |

`render.yaml`에 `FREE_DAILY_LIMIT=1`, `FREE_REQUIRE_IDENTITY=true`로 잡아두었다.
본인인증을 켜두면 계정을 여러 개 만들어 무료 횟수를 무한히 쓰는 것을 막는다.

### 서버가 잠든다

Render 무료는 **15분간 요청이 없으면 컨테이너를 재우고**, 다시 깨어나는 데 약 1분 걸린다.
우리 워커는 DB를 계속 들여다보는 스케줄러라 잠든 동안은 아무것도 처리하지 못한다.

- 사용자가 제작을 누르고 창을 닫으면 → 작업은 대기 상태로 멈춰 있다가 다음에 누가 사이트에
  들어올 때 처리된다. 잃어버리지는 않는다(깨어나면 3초 안에 집어간다).
- 제작 도중에 잠들면 → 그 작업은 잠금이 풀린 뒤 재시도된다. **이미 OpenAI 에 요금이 나간
  호출을 다시 하게 되므로 돈이 두 번 든다.** 최대 3번까지 재시도한다.

깨어 있게 하려면 외부에서 5~10분마다 `/actuator/health`를 호출하면 된다. 다만 무료는
**월 750시간**이고 한 달이 약 730시간이라, 계속 깨워두면 여유가 20시간밖에 없다.
다른 서비스를 하나라도 더 돌리면 한도를 넘긴다.

### 메모리가 빠듯하다

무료는 512MB다. JVM 기본값으로 올리면 부하가 조금만 걸려도 죽는다.
`backend/Dockerfile`의 실행 옵션이 그래서 있다 — 힙을 70%로 묶고, 작은 힙에 맞는 GC 를 쓰고,
시작이 빨라지도록 최적화 컴파일을 생략한다.

## 1. 백엔드 (Render)

### 만들기

1. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
2. GitHub 저장소(`baysix/Prompick`) 연결
3. 저장소 루트의 `render.yaml`을 자동으로 읽는다

### 환경변수 넣기

`render.yaml`에 `sync: false`로 적어둔 값들은 대시보드에서 직접 넣어야 한다.
저장소에 적으면 안 되는 값들이다.

| 키 | 어디서 가져오나 |
|---|---|
| `DB_POOL_URL` | Supabase → Project Settings → Database → Connection string (**포트 6543**) |
| `DB_SESSION_URL` | 같은 곳 (**포트 5432**) |
| `DB_USERNAME` | 같은 곳 |
| `DB_PASSWORD` | 같은 곳 |
| `SUPABASE_URL` | Supabase → Project Settings → API |
| `SUPABASE_SECRET_KEY` | 같은 곳의 `sb_secret_...` |
| `PROMPICK_MASTER_KEY` | 로컬 `.env`에 있는 값을 그대로 |
| `CORS_ALLOWED_ORIGINS` | 프론트 주소 (아래 3번에서 정해진다) |

> **`PROMPICK_MASTER_KEY`는 한 번 정하면 바꾸지 않는다.** 이 값으로 제공사 API 키를
> 봉인해 두기 때문에, 바뀌면 저장된 키를 읽지 못한다.

### 마이그레이션

Flyway 가 서버 시작할 때 알아서 돈다. 따로 실행할 것이 없다.

로컬 DB 와 운영 DB 가 같은 Supabase 프로젝트라면 이미 V33까지 적용되어 있어 아무 일도
일어나지 않는다. 운영용 프로젝트를 따로 만들었다면 V1부터 순서대로 실행된다.

### 제공사 키

`.env`가 아니라 **관리자 화면에서 넣는다.** 배포 후:

1. 운영자 계정으로 로그인
2. 관리자 → 제공사 키 → OpenAI → 키 넣기

## 2. 프론트 (Vercel)

1. [vercel.com](https://vercel.com) → New Project → 같은 저장소
2. **Root Directory 를 `frontend`로** 지정 (이게 빠지면 빌드가 실패한다)
3. 환경변수:

| 키 | 값 |
|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `https://prompick.onrender.com/api/v1` |
| `API_BASE_URL` | 같은 값 (서버 컴포넌트가 쓴다) |
| `NEXT_PUBLIC_SITE_URL` | `https://prompick.vercel.app` |
| `NEXT_PUBLIC_SUPABASE_URL` | 로컬과 동일 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 로컬과 동일 |

> `NEXT_PUBLIC_`이 붙은 값은 **브라우저로 그대로 나간다.** `SUPABASE_SECRET_KEY`나
> `OPENAI_API_KEY`를 여기 넣으면 누구나 꺼내 쓸 수 있다.

## 3. 서로 연결하기

순서가 있다. 상대 주소를 알아야 설정할 수 있기 때문이다.

1. Render 배포 → 주소를 받는다 (`https://prompick.onrender.com`)
2. Vercel 환경변수에 그 주소를 넣고 배포 → 주소를 받는다
3. Render 의 `CORS_ALLOWED_ORIGINS`에 Vercel 주소를 넣고 재시작

CORS 는 **정확히 일치하는 주소만** 허용한다. Vercel 미리보기 배포는 매번 주소가 달라지므로
따로 추가해야 한다. 와일드카드(`https://*.vercel.app`)를 쓰지 않는 이유는, 그러면 누가 만든
Vercel 앱이든 우리 API 를 부를 수 있게 되기 때문이다.

4. Supabase → Authentication → URL Configuration 에 Vercel 주소 추가
   (로그인 후 돌아올 주소다. 빠지면 로그인이 끝나고 엉뚱한 데로 간다)

## 4. 배포 전에 정리할 것

| 항목 | 왜 |
|---|---|
| 관리자 비밀번호 변경 | 개발용 `prompick-admin-2026`이 그대로다 |
| 예시 이미지 교체 | 지금 예시가 공개 버킷에 있어 **로그인 없이 누구나 본다**. 아이 얼굴이 검색에 노출된다 |
| 템플릿 요금 정하기 | 전부 무료다. 사용자가 늘면 매출 없이 원가만 나간다 |
| 테스트 데이터 정리 | 관리자 지급 프롬비, `cmp-` 테스트 작업 |

### 아직 없는 것

- **결제** — 프롬비가 느는 길이 관리자 지급뿐이다. 유료로 열려면 결제 연동이 먼저다.
- **워터마크** — 무료 결과물에 표시가 들어가도록 기록만 하고 실제로 그리지는 않는다.
